本机同步代理

未连接

网页不能直接执行本机程序（浏览器安全边界），所以由本机一个只监听 127.0.0.1 的小服务代跑脚本。启动它以后，点「立即同步」就会： 挑最新台账 → 抽取 → 型号归一 → 生成工作台数据，并把进度实时显示在这里。

代理未连接 —— 在项目目录下打开命令行执行：
python wb_sync_agent.py
首次使用先复制配置模板并填写台账路径：
copy wb-sync.config.example.json wb-sync.config.json
启动后浏览器打开 http://localhost:8765/，那里是同源的完整工作台， 体验最顺（本页是 GitHub 上的版本，属跨源访问，同样可用）。

为什么不用别的办法：自定义协议（wb-sync://）在页面上无法得知 执行结果，也做不了进度；纯文件监听则做不到「点一下就开始」。 本机小服务是唯一既能触发、又能拿到进度与结果的方案。

在线地址同步

为什么金山/腾讯文档的链接拉不到？
三个硬障碍，不是没做，是浏览器不允许： ① 这类在线表格是 JS 动态渲染的页面，直连拿到的是空壳 HTML，不是数据； ② 它们不开放跨域（CORS），网页发起的请求会被浏览器直接拦掉； ③ 开放接口需要 Access Token，而令牌的密钥不能放在公开网页里。

能用的做法（任选）：
· 本地小服务：在放数据的机器上跑 python -m http.server 8000，然后填 http://localhost:8000/workbench-data.json —— 数据不出你的局域网；
· 可跨域的直链：任何允许 CORS 的地址（自建接口、GitHub Raw 等）；
· 走定时任务：让服务器定时拉在线表格、生成 workbench-data.json，页面只拉这个结果文件。

数据来源与更新方式

数据不经过网络。本页是纯前端应用，数据由你在本机选择的数据文件加载， 不上传、不联网、不经过任何服务器。台账明细不会离开这台设备。

同步步骤：台账更新后，本机运行 python src/build_workbench_data.py 生成新的 workbench-data.js → 回到本页点右上角 ⟳ 同步数据 → 选择该文件。 页面会记住这个文件，之后点同步即直接重读，无需再选。
怎么判断数据是新的：顶栏会显示数据快照日期与同步时间。
安全库存：台账里没有这个字段，它是管理参数。脚本首次运行会生成 safe_stock.csv 模板（按近 7 日出库量给建议值），修订后重跑即生效。
安装到桌面：用 Chrome / Edge 打开本页，点顶栏「安装到桌面」， 之后可像普通应用一样独立窗口打开，断网也能用。

判定规则

短缺预警：当前库存 < 安全库存，或可用库存不足近 7 日出库量的 30%（约 2 日消耗）。

积压识别：距最后一次出库超过 180 天，且仍有库存。

库存健康度：1 −（短缺项 + 积压项）/ 物料总品种数。

阈值取 180 天而非 90 天：本台账覆盖两年跨度，用 90 天会把正常低频物料一并误判为积压。 两个阈值都可在页面脚本顶部的 OVER_DAYS / COVER_RATIO 中调整。
以上判定由程序按固定阈值计算，AI 仅负责将结果组织成可读的分析结论， 不参与数值计算，以保证结论与数据一致、可复核。
