# 数据管理规范

台账数据的目录结构、命名规则、字段要求与便携方案。
**目标：格式问题在源头解决，脚本不用再兜底猜。**

---

## 一、一条铁律：分三层，手只碰第一层

```
① 原始层   集成商交来的文件 + 在线台账     ← 只进不改，人手操作
② 规范层   标准 CSV（脚本抽取生成）        ← 永不手工编辑
③ 产物层   工作台数据、月报、图表          ← 脚本生成，可随时重跑
```

**为什么这条最重要**

- 原始层只读 → 任何时候都能从头重跑，脚本改进了不用回头修数据
- 规范层不手工改 → 不会出现「数据到底以哪份为准」的扯皮
- 产物层可再生 → 删了也不心疼，跑一遍就有

> 反面教材：在规范层手工补过数据，下次重跑全被覆盖 —— 白干，还找不到丢的是哪些。

---

## 二、目录结构

```
材料台账/
├─ 00-原始/                  ← 集成商交来的文件，按 集成商/年 归档
│   ├─ 集成商A/2026/
│   ├─ 集成商B/2026/
│   └─ 集成商C/2026/
├─ 10-规范化/                ← 脚本产出，不手工改
│   ├─ 入库明细.csv
│   ├─ 出库明细.csv
│   ├─ 退料明细.csv
│   ├─ 库存汇总.csv
│   └─ 型号映射.csv
├─ 20-快照/                  ← 每日/每月库存快照，算趋势用
├─ 30-产物/                  ← 工作台数据、月报
├─ 90-归档/                  ← 过期的原始文件与旧产物
└─ _规范/                    ← 填报模板、字段字典、本规范
```

**别再往一个目录里堆**。现状是 `材料管理/` 根目录下混着日报、汇总表、项目清单、
会议纪要、以及 9 个 `~$` 残留锁文件 —— 找一份数据要翻半天，还容易拿错版本。

## 三、命名规范（改这一条，收益最大）

### 统一格式

```
{集成商}_{数据类型}_{YYYYMMDD}.xlsx
```

| 数据类型 | 说明 |
|---|---|
| `入库明细` | 到货/入库流水 |
| `出库明细` | 发料/领料流水 |
| `退料明细` | 退料、废料 |
| `库存` | 某时点库存快照 |
| `盘点` | 盘点记录 |

### 例子

| 现有文件名 | 问题 | 规范后 |
|---|---|---|
| `XX材料库存(10月26日).xlsx` | 中文日期、无年份 | `集成商A_库存_20261026.xlsx` |
| `XX材料库存(2026.1.27实际）.xlsx` | 点分隔、全角括号、带"实际" | `集成商A_库存_20260127.xlsx` |
| `XX材料库存8月8日).xlsx` | **括号不配对** | `集成商A_库存_20260808.xlsx` |
| `XX-材料库存2025-08-08.xlsx` | 连字符、词序倒 | `集成商B_库存_20250808.xlsx` |
| `材料库存（XX）_20250106.xlsx` | 集成商写在括号里 | `集成商C_库存_20250106.xlsx` |

### 硬性规则

- 日期一律 **8 位 `YYYYMMDD`**，不要「9月8日」「2026.1.27」
- 分隔符一律**下划线**
- 集成商用**固定简称**，不要一会儿写全称、一会儿写简称
  （简称名单从外部配置读入，见下方「入库前必须过校验」）
- **不要**出现「最终版」「修改后」「(1)」「副本」「实际」这类词
- **不要**在文件名里写单位、不要留多余括号

**好处**：脚本能从文件名直接读出集成商、类型、日期，不用人工指定；
文件按名排序就等于按时间排序。

## 四、字段规范（发给集成商的要求）

这一节是**发给集成商照做的**。格式问题在源头解决，比在脚本里兜底省十倍力气。

### 硬性要求

1. **用统一模板**（见 `_规范/填报模板_*.xlsx`），不要自己另起格式
2. **表头固定在第 1 行**，不要合并单元格、不要多行表头
3. **日期**用 `2026-09-08` 格式
   —— 不要 `9月8日`（没有年份，脚本只能猜）、不要 `2026.9.8`
4. **数量列纯数字**，不要 `约500`、`1,200`、`500个`
5. **单位单独一列**，不要混进数量里
6. **不要在中间插入汇总行、空行、说明行** —— 汇总行会被当成数据读进来
7. **一个文件只放一类数据**，不要把入库出库库存塞在同一个文件的不同表里
8. 型号写法如有变化，**在备注列说明**，不要直接改

### 为什么较真

历史上真实踩过的坑：

| 坑 | 后果 |
|---|---|
| 日期混排中文与标准格式 | 当月统计成 0 笔，排查半天 |
| 数量列混入「约500」 | 汇总全废，得手工核对 |
| 单位不统一（同一物料米/个混用） | 汇总金额算错 |
| 同一物料多种写法（RRU-5278 / RRU5278-d） | 被拆成两项，库存看起来是两份 |
| 表里残留 100 万行格式 | 读取卡死几十分钟 |
| 公式残留的空白行 | 多出大量空记录 |

## 五、入库前必须过校验

收到文件**先检查，再放进 `00-原始/`**：

```bash
python src/check_incoming.py "<文件路径>"
python src/check_incoming.py --dir "<目录>"           # 批量
python src/check_incoming.py "<文件>" --std 标准型号表.csv
python src/check_incoming.py --selftest               # 自检工具本身
```

**集成商名单从外部配置读入**，仓库里不存真实名单（避免把供应链信息写进公开代码）：

```bash
python src/check_incoming.py --suppliers 集成商A,集成商B,集成商C
# 或长期生效：环境变量 LEDGER_SUPPLIERS，或同目录 suppliers.json
```

优先级：`--suppliers` > 环境变量 `LEDGER_SUPPLIERS` > `suppliers.json` > 空（不校验）。
参考 `suppliers.example.json`。**未配置时脚本仍可用，只是不校验集成商、命名建议会标注需人工补。**

检查内容：

| 项 | 检查什么 |
|---|---|
| 文件名 | 是否符合命名规范，并给出**建议的新名字** |
| 读取 | 行数、列数、有几个工作表（会提示只读了第一个） |
| 表头 | 关键列是否齐全 |
| 日期 | 能否全部解析；有几行是中文格式且无年份 |
| 数量 | 有没有非数值、负数 |
| 单位 | 取值是否过多（说明口径不统一） |
| 空行 | 有多少关键列为空的行 |
| 型号 | 是否都在标准型号表里，不在的列出来待人工归并 |

**退出码**：0 = 无错误；1 = 有错误。可以据此决定「放行」还是「退回集成商」。

> 校验脚本只读，不会修改文件。

## 六、便携：两台电脑 + 手机怎么共用

数据不能上网（否则等于公开台账），所以用**同步盘**而不是云表格：

```
数据根目录放在 OneDrive 同步文件夹
        ↓
两台电脑登录同一 OneDrive → 自动双向同步
        ↓
脚本用环境变量 LEDGER_DIR 指向它，路径不写死
```

设置：

```powershell
# Windows PowerShell
$env:LEDGER_DIR = "C:\Users\<你>\OneDrive\材料台账"
# 想永久生效：
[Environment]::SetEnvironmentVariable("LEDGER_DIR", "C:\...\材料台账", "User")
```

脚本读不到 `LEDGER_DIR` 时，会回落到仓库内 `material-system/data/`（该目录不入版本库）。

### 方案对比

| 方案 | 评价 |
|---|---|
| **OneDrive / 坚果云同步盘** | ✅ 推荐。自动双向、有版本历史、手机能只读查看 |
| 在线表格（金山文档）当文件仓库 | ❌ 不适合。有大小/格式限制，不适合当原始文件归档 |
| U 盘 / 移动硬盘 | ❌ 容易丢、容易忘记同步 |
| 直接放某个固定盘符 | ⚠️ 换电脑就断，路径写死脚本就得改 |

> 分工建议：**在线台账负责「当前活数据」**（人工维护预警线、项目对应），
> **同步盘里的本地目录负责「原始归档 + 派生结果」**。两者不要互相替代。

## 七、每月固定动作

1. 收齐三家的文件 → 逐个跑 `check_incoming.py` → 有错退回重报
2. 通过的文件改名入库到 `00-原始/{集成商}/{年}/`
3. 跑抽取与归并脚本 → `10-规范化/`
4. 人工确认「待归并型号」清单（脚本不会自动合并）
5. 跑工作台数据生成 → `30-产物/`
6. 生成月报
7. 上月的原始文件移到 `90-归档/`

## 八、常见问题

**Q：集成商不按模板报怎么办？**
先跑校验，把报告连同这份要求一起发回去。报告里写了具体哪行哪列有问题，
比笼统说「格式不对」有效得多。

**Q：历史文件要不要全部改名？**
不用。只改**新收的**，历史文件留在 90-归档 按原样存。
改名历史文件容易改错、也容易破坏已有引用。

**Q：`~$` 开头的文件是什么？**
Excel 异常退出的残留锁文件，可以直接删。看到它们说明有文件没正常关闭。

**Q：规范层手工改过的数据怎么办？**
改成「在原始层修正 → 重跑脚本」的流程。手工改规范层的数据下次重跑就没了。
