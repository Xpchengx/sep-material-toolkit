# 室内分布材料台账工具链

把仓库物料台账（金山文档 / Excel 维护）自动转成**可查询的工作台页面**与**月度报表**。

> ⚠️ **本仓库只保存工具代码，不保存任何业务数据。**
> 台账明细、生成物、盖章文件、成员信息一律通过 `.gitignore` 排除，不要提交。

---

## 这套工具解决什么

物资台账通常维护在在线表格里，人工查数、汇总、出报表都很费时。这套脚本把链路自动化：

```
金山文档 / Excel 台账
    ↓  extract.py            抽取为结构化 CSV
原始明细（入库 / 出库 / 退料 / 盘点 / 库存汇总）
    ↓  normalize.py          型号归一（多种写法 → 标准编码）
    ↓  build_workbench_data.py   计算工作台所需指标
workbench-data.js
    ↓
HTML 工作台（库存总览 / 预警 / 台账 / 日报）
    ↓  build_monthly_report.py
月度报表 Word
```

## 数据怎么组织

详细规范见 [`docs/数据管理规范.md`](docs/数据管理规范.md)。三条要点：

**1. 分三层，手只碰第一层**

```
① 原始层   集成商交来的文件 + 在线台账   ← 只进不改，人手操作
② 规范层   标准 CSV（脚本抽取生成）      ← 永不手工编辑
③ 产物层   工作台数据、月报、图表        ← 脚本生成，可随时重跑
```

**2. 命名统一**：`{集成商}_{类型}_{YYYYMMDD}.xlsx`
（如 `集成商A_库存_20260908.xlsx`）。日期一律 8 位，分隔符一律下划线，
不要「9月8日」「最终版」「(1)」这类写法。

**3. 收到文件先过校验**

```bash
python src/check_incoming.py "<文件或目录>" --std 标准型号表.csv
```

检查文件名、表头、日期可解析率、数量是否纯数字、单位取值是否统一、
空行、型号是否在标准表里。**退出码 0=放行，1=退回**。

### 数据目录放在哪

数据不能上网，用**同步盘**（OneDrive / 坚果云）跨设备共用，脚本通过环境变量定位：

```powershell
$env:LEDGER_DIR = "C:\Users\<你>\OneDrive\材料台账"
```

读不到该变量时回落到仓库内 `material-system/data/`（不入版本库）。

## 四种数据接法

页面是纯前端的，**数据全程留在本机**。四种把数据喂进来的方式，推荐顺序如下。

### ① 本机同步代理（推荐：点一下就跑脚本）

浏览器**不允许**网页执行本机程序，这是安全边界，绕不过去。所以在本机跑一个
只监听 `127.0.0.1` 的小服务，由它代跑脚本：

```
网页点「同步」 → POST 到本机代理 → 代理依次跑脚本 → 回传进度与结果 → 页面刷新数据
```

```bash
# 首次：复制配置模板并填台账路径
copy wb-sync.config.example.json wb-sync.config.json

# 启动（按 Ctrl+C 停止）
python wb_sync_agent.py

# 然后浏览器打开这个地址 —— 同源，体验最顺
http://localhost:8765/
```

它同时把仓库当静态站点服务，并把 `/workbench-data.js`、`/wb-meta.js`
映射到 `output/` 下的最新文件，所以**打开就是数据最新的完整工作台**。

GitHub Pages 上那份页面也能连它（跨源，由服务端 CORS 白名单放行）。
「数据源」页里能看到连接状态、逐步进度与失败时的输出。

**安全性**：只绑 `127.0.0.1`（局域网访问不到）、校验 Host 头挡 DNS rebinding、
CORS 只放行白名单来源而不是 `*`。需要更严可以开 `requireToken`。

> 为什么不换别的办法：自定义协议（`wb-sync://`）在页面上拿不到执行结果、
> 也做不了进度；纯文件监听做不到「点一下就开始」。本机小服务是唯一
> 既能触发、又能拿到进度与结果的方案。

### ② 拖拽（最省事，不必装代理）

把集成商发来的 xlsx 直接拖到页面上。页面会自己：
认表（含「型号」列且含「库存」或「日期+数量」）→ 认集成商与类型 →
按标准型号归并 → 重算库存与近 7 日出入库 → 刷新全部视图。

生成好的 `workbench-data.json` 也可以直接拖进来。

### ③ 选择文件

「数据源」页的「选择文件…」同 ②。

### ④ 在线地址同步

「数据源」页可以填一个地址点同步。**注意：金山/腾讯文档的分享链接拉不到**，原因是
① 这类页面是 JS 动态渲染的，直连只拿到空壳；② 不开放 CORS，请求会被浏览器拦掉；
③ 开放接口的令牌密钥不能放在公开网页里。能用的做法见页面上的说明
（本地 `http.server`、可跨域直链、或服务端定时任务）。

### 更新追踪

每次载入都会记下每张表的**数据日期**（取表内最新流水日，或文件名里的日期）与载入时间。
「数据源」页按阈值分三级展示：正常 / 偏旧 / 长期未更新；
总览页出现偏旧或长期未更新的表时会给提醒横幅，侧栏徽标显示条数。阈值可在界面上调。

> 数据日期取「文件名里的日期」优先于「流水里的最大日期」——流水里常混入
> 误录的异常日期（比如写成半年后），拿它当快照会把整个 7 日窗口带偏。

## 同步链路：脚本怎么串起来

```
pick_sources.py       扫描台账目录，挑出每个集成商**最新的一份**
      ↓ 写 sources.json（含文件绝对路径 + 角色）
extract.py            读 sources.json，按角色处理三种不同格式的台账 → 标准 CSV
      ↓
normalize.py          型号归一（机械归一 + 人工规则 + 相似度候选）
      ↓
build_workbench_data.py  汇总计算 → workbench-data.js / wb-meta.js
```

### 两个曾经踩过的坑

**源文件路径写死**。原来 `extract.py` 里的路径是硬编码的，新台账到了不会自动用上，
「点了同步」其实同步的是旧数据。现在由 `pick_sources.py` 自动挑最新，写进 `sources.json`。

**名称与格式耦合**。三家台账的**格式**不同（一家多一列「月份」、一家有「设计明细」表），
代码原本靠**名字**分支（`if tag == "集成商B"`），于是改名就崩。现在改成按**角色**分支：

| 角色 | 特征 |
|---|---|
| A | 无「月份」列；盘点表 账面/实盘/差异 在第 4~6 列 |
| B | 有「月份」列；盘点表列位在第 7~9 列 |
| C | 有「设计明细」表；盘点表列位在第 5~7 列 |

角色到名称的对应写在 `wb-sync.config.json` 里，**换集成商或改标签都不用动代码**。

### 年份推断：文件名没写年份怎么办

「XX材料库存(10月26日).xlsx」这种没有年份，而这份文件其实是 **2025** 年的
（mtime 2025-10-27）。按目录里最大年份推会误判成 2026，结果选中一份比现有数据还旧的表。

做法：在 `[mtime年-1, mtime年, mtime年+1]` 里挑**与 mtime 最接近**的那个。
比「用目录最大年份」可靠得多。

## 三层数据与两种实现

```
① 原始层   集成商交来的 xlsx            ← 只进不改
② 规范层   标准 CSV（Python 抽取生成）   ← 永不手工编辑
③ 产物层   工作台数据 / 月报             ← 脚本生成
```

有**两条**算出工作台数据的路径，口径必须一致：

| | 计算位置 | 用途 |
|---|---|---|
| Python | `build_workbench_data.py` | 批量、出月报、生成 `wb-meta.js` |
| JavaScript | `wb-merge.js` | 页面里拖入即算，不用装 Python |

规则只维护一份：分类规则、型号归一表、安全库存、阈值都由 Python 生成到
`wb-meta.js`，页面读取应用。**新增或修规则请改 Python 端**，然后重跑脚本。

### 一个真实的坑：无年份日期跨年

台账里常见「序列号 + 无年份中文日期」混排，而中文那段往往**跨年**：

```
… 8月7号 … 12月24号 │ 1月5号 … 9月2号
      上一年          │    下一年
```

无论统一补哪一年都会算错。`wb-merge.js` 的 `parseDateColumn` 按**行序检测月份回绕**
（月份变小即进一年）来推，且**绝对日期不参与重置**——否则夹在中间的序列号
会把年份又拉回去。本项目的实际影响是近 7 日入库少算一笔 1.26 万米馈线。

根因是源头日期没写年份。**根治办法是要求集成商按 `YYYY-MM-DD` 填报**
（见 `docs/数据管理规范.md`）。

## 快速开始

### 0. 指定台账目录

脚本通过环境变量 `LEDGER_DIR` 定位台账文件（不写死在代码里）：

```bash
# Windows (PowerShell)
$env:LEDGER_DIR = "D:\path\to\材料管理"
# Linux / macOS / Git Bash
export LEDGER_DIR="/path/to/材料管理"
```

不设置时默认使用仓库内 `material-system/data/`（该目录不入库）。

### 1. 生成工作台数据

```bash
cd material-system
python src/build_workbench_data.py
# 输出 output/workbench-data.js
```

参数：

| 参数 | 说明 |
|---|---|
| `--src` | 明细 CSV 目录（默认 `material-system/out`） |
| `--out` | 输出的 `workbench-data.js` 路径 |
| `--snapshot` | 快照日期 `YYYY-MM-DD`（默认取明细中最大日期） |
| `--days` | 趋势天数（默认 14） |
| `--safe-config` | 安全库存 CSV（默认 `out/safe_stock.csv`） |
| `--reset-safe` | 重新生成安全库存模板 |
| `--bundle` | 另出一份数据内联的单文件 HTML |

### 2. 打开工作台并同步数据

工作台是一个 **PWA**，页面本身不含任何业务数据。

- **本地打开**：双击 `index.html`，与数据文件同目录时会自动加载。
- **在线打开**：见下方「部署」。在线版默认是演示数据。
- **同步数据**：点右上角 **⟳ 同步数据**，选择本机生成的
  `workbench-data.json`（或 `.js`）。页面会记住该文件，之后点同步即直接重读。

> **数据不经过网络。** 页面是纯前端应用，数据只加载进本机内存，
> 不上传、不联网、不经过任何服务器。部署在公开站点上也不会附带台账明细。
> 数据文件同时被 `.gitignore` 排除。

### 3. 安装到桌面

用 Chrome / Edge 打开，点顶栏「安装到桌面」，之后可独立窗口打开，断网也能用
（Service Worker 缓存应用外壳）。

### 4. 部署到 GitHub Pages

仓库 Settings → Pages → Source 选 `main` 分支根目录。站点形如
`https://<用户>.github.io/<仓库>/`。

页面里所有资源都用了相对路径，放在仓库子路径下也能正常工作。
改动页面后请把 `sw.js` 顶部的 `VERSION` 加一，否则访客拿到的是旧缓存。

## 工作台页面包含

| 视图 | 内容 |
|---|---|
| 总览 | 5 项 KPI、库存总量趋势、分类占比、需关注物料 |
| 短缺预警 | 低于安全库存或供应紧张的物料，按紧急程度排序 |
| 积压识别 | 长期无出库且仍有库存的物料 |
| 物料台账 | 全量明细，支持检索、分类、排序 |
| 库存变化 | 趋势图 + 近 7 日出入库比对 |
| 库存日报 | 一键执行五步流程并生成完整日报 |
| 推送记录 | 日报定向推送历史 |

### 判定规则

```
短缺 = 库存 < 安全库存  或  库存 < 近7日出库 × 0.3（约 2 日消耗）
积压 = 距最后出库 > 180 天  且  仍有库存
健康度 = 1 −（短缺项 + 积压项）/ 物料总品种数
```

阈值在页面脚本顶部提为常量，可按管理口径调整：

```js
const OVER_DAYS = 180;     // 积压判定天数
const COVER_RATIO = 0.3;   // 供应紧张系数
```

> 阈值取 180 天而非 90 天：台账通常跨年度，90 天会把正常低频物料误判为积压。
> 改阈值前建议先看一遍实际的滞留天数分布。

## 数据接入方式

页面本身**无法直连**在线表格或内部系统（浏览器没有登录态，跨域会被拦）。
正确做法是数据在外部生成后喂给页面，本仓库的脚本就是这一层。

两种接数方式：

1. **连接器 / 脚本拉取**（推荐）：用平台的开放接口或连接器拉取台账，落成 CSV，
   再跑 `build_workbench_data.py`。
2. **手工导出**：把台账另存为 xlsx / CSV 后运行抽取脚本。

要定时自动刷新，可用系统的定时任务调度「拉取 → 重算 → 更新页面」这条链。

## 关于安全库存

**安全库存是管理参数，台账里通常没有。** 判定短缺必须依赖它，所以：

- 若源表已预留「安全库存」列 → 建议直接在源表维护，脚本会优先读取；
- 否则脚本首次运行会生成 `safe_stock.csv` 模板，给出保守建议值
  （按近 7 日出库量推算），**必须人工确认后使用**。

建议值宁小勿大：给大了会把正常库存误判成短缺。

---

## 数据自检

生成脚本会输出预警占比，**超过 30% 通常是阈值没调准**而不是数据有问题：

```
预警情况 : 短缺 13 项、积压 15 项，占比 27%（健康度 73%）
[OK] 预警占比 27%，在合理区间。
```

生成后建议核对：**趋势末端值应与库存合计一致**（趋势由当前库存倒推，
倒推时只能统计入选物料的流水，否则会对不上）。

## 已知限制

- 明细表的日期列常为混合格式（标准日期与「8月6号」这类中文文本混排，且中文格式不带年份），
  解析时需按行序做年份推断。
- 跨单位合计（米 / 个 / 台 / 副 混加）只有趋势意义，不能当作实物量。
- 型号归一的候选清单需要人工确认，脚本不会自动合并。
